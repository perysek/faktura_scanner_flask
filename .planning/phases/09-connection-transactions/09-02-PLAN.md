# Plan 09-02: Transactional Integrity for Multi-Step Operations

## Goal

Wrap multi-step appointment operations (create, complete, update) in explicit database transactions so that a failure at any step rolls back ALL previous steps — no partial state.

## Context

Current problem in `services/appointment_service.py`:
- `create_appointment()`: Steps 4-5 each call separate repo methods that each get their own connection from `g.db` and commit independently. If step 5 (add services) fails after step 4 (create appointment) committed, an orphaned appointment exists with no services.
- `complete_appointment()`: Steps 4-6 (create income, update status, update price, update client) each commit independently. If step 5 fails after step 4, income record exists but appointment is still `in_progress`.
- `update_appointment()`: Steps 5-7 (update appointment, delete old services, add new services, handle income) each commit independently. If service re-insertion fails after deletion, services are lost.

The root cause: each repository method calls `conn.commit()` independently. The `BaseRepository.transaction()` context manager exists but is not used by the standalone repos (AppointmentRepository, IncomeRepository etc. use `get_db_connection()` directly).

**Solution approach:** Introduce a `managed_transaction` context manager at the `config/database.py` level that:
1. Gets a connection from the pool (or reuses the request's `g.db`)
2. Disables autocommit for the scope
3. Commits on success, rolls back on exception
4. The service layer uses this to wrap multi-step operations
5. Individual repo methods that are called within a transaction must NOT commit — they should detect "am I inside a managed transaction?" and skip commit.

**Design decision:** Use a Flask `g` flag (`g._in_transaction = True`) to signal to repos that they should NOT auto-commit. The transaction context manager sets this flag and handles commit/rollback. Individual repo methods check for this flag before calling `conn.commit()`.

Existing interfaces from `config/database.py` (from Plan 09-01):
```python
def get_db_connection() -> psycopg2.extensions.connection:
    return DatabaseConnection.get_connection()

class DatabaseConnection:
    @classmethod
    def get_connection(cls) -> connection: ...
    @classmethod
    def close_connection(cls): ...
```

Existing `BaseRepository.transaction()` context manager (line 83-100 of base_repository.py):
```python
@contextmanager
def transaction(self):
    conn = self._get_conn()
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
```

## Tasks

### Task 1: Add managed_transaction context manager + conditional commit logic
**Files:** `config/database.py`, `services/appointment_service.py`
**Change:**

In `config/database.py`:
1. Add a `managed_transaction` context manager function:
   ```python
   @contextmanager
   def managed_transaction():
       """Wrap multiple repo calls in a single transaction.
       
       Usage:
           with managed_transaction():
               repo_a.create(...)
               repo_b.create(...)
           # commits on success, rolls back on any exception
       
       Repo methods that normally call conn.commit() will skip the commit
       when g._in_transaction is True.
       """
       conn = DatabaseConnection.get_connection()
       g._in_transaction = True
       try:
           yield conn
           conn.commit()
       except Exception:
           conn.rollback()
           raise
       finally:
           g._in_transaction = False
   ```

2. Add `is_in_transaction() -> bool` helper:
   ```python
   def is_in_transaction() -> bool:
       return getattr(g, '_in_transaction', False)
   ```

3. Update `get_db_connection()` — no changes needed, it still returns the same connection.

In `services/appointment_service.py`:
1. Add `from config.database import managed_transaction` import
2. Wrap `create_appointment()` steps 4-5 (create appointment + add services) in `with managed_transaction():` block. Move the repo calls that do writes inside the block.
3. Wrap `complete_appointment()` steps 4-6 (create income + update status + update price + update client last_visit) in `with managed_transaction():` block.
4. Wrap `update_appointment()` steps 5-7 (update appointment + delete services + add services + income handling) in `with managed_transaction():` block.

**Key detail for repo compatibility:** The standalone repos (AppointmentRepository, IncomeRepository, etc.) use `with get_db_connection() as conn:` and then `conn.commit()`. The psycopg2 connection context manager does NOT close the connection — it commits on clean exit. When `g._in_transaction` is True, these `conn.commit()` calls must be suppressed. Two approaches:

**Approach A (preferred — minimal change):** In each multi-step service method, DO NOT modify repos. Instead, set `conn.autocommit = False` (which is already the default for psycopg2) and rely on the fact that individual `conn.commit()` calls within the `managed_transaction` block are harmless IF the repos all share the same `g.db` connection — each `conn.commit()` just commits the current transaction and starts a new implicit one. This breaks atomicity.

**Approach B (correct):** Add a `_safe_commit(conn)` helper to `config/database.py` that checks `is_in_transaction()` and skips commit if True. Then update the repos that do explicit `conn.commit()` within their methods: `AppointmentRepository`, `AppointmentServiceRepository`, `IncomeRepository`, `ClientRepository` (update_last_visit only). Replace `conn.commit()` with `_safe_commit(conn)`. This is the correct approach because individual commits within a managed transaction would break atomicity.

Use **Approach B**. Add `_safe_commit`:
```python
def safe_commit(conn):
    """Commit unless inside a managed_transaction scope."""
    if not is_in_transaction():
        conn.commit()
```

Update these repo files to use `safe_commit`:
- `repositories/appointments/appointment_repository.py` — replace `conn.commit()` with `safe_commit(conn)` in all write methods (create, update, update_status, update_total_price, soft_delete, restore)
- `repositories/appointments/appointment_service_repository.py` — replace `conn.commit()` in add_service, update_service, delete_service, delete_all_for_appointment
- `repositories/appointments/income_repository.py` — replace `conn.commit()` in create, delete_by_appointment
- `repositories/clients/client_repository.py` — replace `conn.commit()` in update_last_visit

Each file: add `from config.database import safe_commit` import, search-replace `conn.commit()` with `safe_commit(conn)`.

Also update `BaseRepository._execute()` and `_execute_insert()` — they call `conn.commit()`. Replace with `safe_commit(conn)`.
