# Plan 08-03: Refactor get_multi_employee_schedule from N+1 to Single JOIN Query

## Goal

Replace the per-employee loop in `get_multi_employee_schedule()` that fires one `cursor.execute()` per employee with a single JOIN query that fetches all employees' appointments in one database round-trip, then partitions the results in Python.

## Context

**File:** `repositories/appointments/appointment_repository.py`

**Current N+1 pattern (lines ~254-280):**

```python
# Step 1: one query to get employees
cursor.execute(query_employees, ...)
employees = [dict(row) for row in cursor.fetchall()]

# Step 2: N queries — one per employee
schedules = {}
query_appointments = """
    SELECT a.*, c.first_name || ... , STRING_AGG(s.name, ', ') as service_name, ...
    FROM appointments a
    JOIN clients c ON c.id = a.client_id
    JOIN employees e ON e.id = a.employee_id
    LEFT JOIN appointment_services aps ON aps.appointment_id = a.id
    LEFT JOIN services s ON s.id = aps.service_id
    WHERE a.employee_id = %s AND a.appointment_date = %s     -- <-- N executions
    AND a.is_deleted = FALSE
    GROUP BY a.id, c.first_name, c.last_name, c.phone, e.first_name, e.last_name
    ORDER BY a.start_time
"""
for emp in employees:                                        # <-- N+1 loop
    cursor.execute(query_appointments, (emp['id'], schedule_date.isoformat()))
    schedules[emp['id']] = [dict(row) for row in cursor.fetchall()]
```

**Target: single JOIN query replacing the loop**

Fetch all employees' appointments in one query using `IN (employee_id_list)` or, when `employee_ids is None`, fetch all employees with appointments on that date. Partition the flat result into `{employee_id: [rows]}` in Python.

**Existing indexes that make this efficient:**
- `idx_appointments_employee_date (employee_id, appointment_date)` — covers the `WHERE` clause of the new query

**Public interface stays identical:**
```python
def get_multi_employee_schedule(self, schedule_date: date, employee_ids: Optional[List[int]] = None) -> dict:
    # Returns: {'employees': [...], 'schedules': {employee_id: [rows]}}
```

## Tasks

### Task 1: Replace the N+1 loop with a single bulk query

**File:** `repositories/appointments/appointment_repository.py`

**Change:** Rewrite the body of `get_multi_employee_schedule()` — specifically the part after `employees` is fetched. Replace the `for emp in employees` loop with a single query:

```python
# Bulk fetch all appointments for found employees in one query
schedules: dict = {emp['id']: [] for emp in employees}

if employees:
    emp_ids = [emp['id'] for emp in employees]
    placeholders = ','.join(['%s'] * len(emp_ids))
    query_all_appointments = f"""
        SELECT
            a.*,
            c.first_name || ' ' || c.last_name AS client_name,
            c.phone AS client_phone,
            e.first_name || ' ' || e.last_name AS employee_name,
            STRING_AGG(s.name, ', ' ORDER BY s.name) AS service_name,
            STRING_AGG(
                CASE WHEN aps.is_addon = TRUE THEN s.name ELSE NULL END,
                ', ' ORDER BY s.name
            ) AS addon_services
        FROM appointments a
        JOIN clients c ON c.id = a.client_id
        JOIN employees e ON e.id = a.employee_id
        LEFT JOIN appointment_services aps ON aps.appointment_id = a.id
        LEFT JOIN services s ON s.id = aps.service_id
        WHERE a.employee_id IN ({placeholders})
          AND a.appointment_date = %s
          AND a.is_deleted = FALSE
        GROUP BY a.id, c.first_name, c.last_name, c.phone, e.first_name, e.last_name
        ORDER BY a.employee_id, a.start_time
    """
    params = emp_ids + [schedule_date.isoformat()]
    cursor.execute(query_all_appointments, params)
    for row in cursor.fetchall():
        row_dict = dict(row)
        emp_id = row_dict['employee_id']
        if emp_id in schedules:
            schedules[emp_id].append(row_dict)
```

Key differences from current code:
- `ORDER BY s.name` added to `STRING_AGG` for deterministic service ordering (PostgreSQL requires explicit ORDER BY in aggregate for stable results)
- Single `cursor.execute()` replaces the loop
- Python dict partitioning replaces per-query fetches
- `schedules` pre-initialized with `{emp_id: []}` so employees with zero appointments still appear as empty lists (same behavior as before)

Remove the old `query_appointments` variable and the `for emp in employees` loop entirely.

**Commit:** `perf(08-03): replace N+1 per-employee schedule loop with single bulk JOIN query`
