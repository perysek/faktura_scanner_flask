# Plan 08-02: Bound Analytics Repository Unbounded Queries

## Goal

Fix two unbounded full-table scans in `analytics_repository.py`: the `retention_query` CTE that reads all completed appointments without a date filter, and the `first_appointments` CTE in `get_new_clients_monthly()` that also scans all-time history. Add date range filters to the CTEs so they use the existing `idx_appointments_status_date` composite index.

## Context

**File:** `repositories/analytics/analytics_repository.py`

**Problem 1 — `get_client_metrics()` retention query (lines ~238-253):**

```python
retention_query = f"""
    WITH client_visits AS (
        SELECT
            client_id,
            appointment_date,
            LAG(appointment_date) OVER (PARTITION BY client_id ORDER BY appointment_date) as prev_visit
        FROM appointments
        WHERE status = '{AppointmentStatus.COMPLETED}'
        -- NO date filter here — full table scan
    )
    SELECT
        COUNT(CASE WHEN (appointment_date - prev_visit) <= 90 THEN 1 END) * 100.0 /
        NULLIF(COUNT(*), 0) as retention_rate
    FROM client_visits
    WHERE prev_visit IS NOT NULL
        AND appointment_date BETWEEN %s AND %s
"""
```

The CTE reads all completed appointments ever, then filters in the outer WHERE. Fix: add a date filter to the CTE itself. Because LAG() needs the previous visit (which may be before `start_date`), the window needs a lookback buffer. Use `start_date - INTERVAL '180 days'` as the lower bound of the CTE — this captures the prev visit needed for calculating 90-day retention at the start of the period.

**Problem 2 — `get_new_clients_monthly()` (lines ~817-832):**

```python
first_appointments AS (
    SELECT
        client_id,
        DATE_TRUNC('month', MIN(appointment_date))::date AS first_month
    FROM appointments
    WHERE status = '{AppointmentStatus.COMPLETED}'
    -- NO date filter — scans entire history
    GROUP BY client_id
)
```

This is intentionally correct — `first_month` must be the all-time first appointment to correctly classify "new" vs "returning". Add a comment explaining why no date filter is appropriate here (clarification, not a bug fix).

**Problem 3 — `get_visit_frequency_distribution()` (lines ~1038-1044):** already has `appointment_date >= CURRENT_DATE - INTERVAL '12 months'` — no fix needed.

## Tasks

### Task 1: Fix unbounded client_visits CTE in retention_query

**File:** `repositories/analytics/analytics_repository.py`

**Change:** In `get_client_metrics()`, update `retention_query`:

Replace the CTE `WHERE` clause from:
```sql
WHERE status = '{AppointmentStatus.COMPLETED}'
```

With:
```sql
WHERE status = '{AppointmentStatus.COMPLETED}'
  AND appointment_date >= %s - INTERVAL '180 days'
```

Update `cursor.execute(retention_query, (start_date, end_date))` to `cursor.execute(retention_query, (start_date, start_date, end_date))` — prepend `start_date` once as the CTE parameter, then pass `start_date, end_date` for the outer WHERE.

The full updated retention_query becomes:
```python
retention_query = f"""
    WITH client_visits AS (
        SELECT
            client_id,
            appointment_date,
            LAG(appointment_date) OVER (PARTITION BY client_id ORDER BY appointment_date) as prev_visit
        FROM appointments
        WHERE status = '{AppointmentStatus.COMPLETED}'
          AND appointment_date >= %s - INTERVAL '180 days'
    )
    SELECT
        COUNT(CASE WHEN (appointment_date - prev_visit) <= 90 THEN 1 END) * 100.0 /
        NULLIF(COUNT(*), 0) as retention_rate
    FROM client_visits
    WHERE prev_visit IS NOT NULL
        AND appointment_date BETWEEN %s AND %s
"""
```

Execute call becomes:
```python
cursor.execute(retention_query, (start_date, start_date, end_date))
```

**Commit:** `perf(08-02): bound client_visits CTE with 180-day lookback window`

first_appointments AS (
