For each of the three files, apply this transformation pattern to EVERY `except Exception as e:` block:

**Pattern A — Known business logic error (most common):**
The try block contains repository/service calls that can fail with known conditions (not found, validation, conflict). Replace the broad catch with specific raises BEFORE the try, and let remaining exceptions bubble to a generic catch.

BEFORE:
```python
try:
    result = repo.get_by_id(id)
    if not result:
        return jsonify({'success': False, 'error': 'Not found'}), 404
    return jsonify({'success': True, 'data': result})
except Exception as e:
    return jsonify({'success': False, 'error': str(e)}), 500
```

AFTER:
```python
try:
    result = repo.get_by_id(id)
    if not result:
        raise NotFoundError('Zasob nie istnieje')
    return jsonify({'success': True, 'data': result})
except AppError:
    raise
except Exception as e:
    logging.exception('Unexpected error in [handler_name]')
    raise AppError('Wystapil blad serwera')
```

**Pattern B — Pure infrastructure error (rare):**
If the try block only does a DB operation with no business logic branching:

AFTER:
```python
try:
    result = repo.do_something()
    return jsonify({'success': True, 'data': result})
except AppError:
    raise
except Exception as e:
    logging.exception('Unexpected error in [handler_name]')
    raise AppError('Wystapil blad serwera')
```

**Key rules:**
1. Add `import logging` at top of each file if not already present
2. Add `from exceptions import AppError, ValidationError, NotFoundError, ConflictError` at top of each file
3. Every `if not result: return jsonify({'error': 'Not found'}), 404` becomes `if not result: raise NotFoundError('Zasob nie istnieje')`
4. Every `if not data: return jsonify({'error': 'No data'}), 400` becomes `if not data: raise ValidationError('Brak danych')`
5. The `except AppError: raise` line MUST appear before `except Exception` — this lets AppError subclasses (including DatabaseConnectionError from BaseRepository) pass through to the global handler
6. The `except Exception as e:` block logs the full traceback with `logging.exception()` and raises generic `AppError('Wystapil blad serwera')` — NEVER `str(e)`
7. For `appointment_routes.py`: the `except AppointmentError` blocks were already removed in Plan 01. Now also remove the remaining `except Exception as e` blocks using the same pattern. `AppointmentError` (now an `AppError` subclass) will bubble through `except AppError: raise` to the global handler.
8. For `upload_routes.py`: OCR-related exceptions (`OCRExtractionError`, now an `AppError` subclass) will also bubble through `except AppError: raise`.

**Error message language:** Use Polish user-facing messages consistent with existing UI tone:
- 400: `'Nieprawidlowe dane'` or `'Brak danych'`
- 404: `'Zasob nie istnieje'` (or entity-specific: `'Faktura nie istnieje'`, `'Klient nie istnieje'`)
- 409: `'Konflikt danych'`
- 500 (generic): `'Wystapil blad serwera'`
