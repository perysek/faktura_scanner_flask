● ★ Insight ─────────────────────────────────────
  Flask SSE streaming context gotcha: When Flask iterates a generator to build a
   streaming response, it does so after the initial route handler returns. By
  default, the request/application context (which holds g) is torn down between
  the handler returning and the generator being iterated. stream_with_context()
  is Flask's purpose-built fix — it keeps the context alive for the entire
  duration of the generator's execution.
  ─────────────────────────────────────────────────

  The fix is simple: stream_with_context is missing from the import and the
  generate() call. This is a classic Flask SSE pitfall.

● ★ Insight ─────────────────────────────────────
  PostgreSQL's "aborted transaction" cascade: Unlike SQLite (which just returns
  an error per statement), PostgreSQL marks the entire connection's transaction
  as poisoned after any error. Every subsequent SQL command on that connection
  returns "current transaction is aborted" until you issue a ROLLBACK. Since all
   invoices share the same g.db connection, one duplicate constraint violation
  poisons all subsequent saves in the same request.
  ─────────────────────────────────────────────────

  The fix: call conn.rollback() in the except block after each DB failure. Also,
   the duplicate check uses SQLite's error string — needs to match PostgreSQL's
  wording.
