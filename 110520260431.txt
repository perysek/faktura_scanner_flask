● ★ Insight ─────────────────────────────────────
  The conflict-check SQL uses the classic interval overlap test: A.start < B.end
   AND A.end > B.start. The query is built dynamically (not with %s IS NULL
  inline) because psycopg2 can't use %s as a NULL-test subject on the left side
  of IS NULL. Dynamic query building here is more readable and avoids obscure
  cast tricks.

  ★ Insight ─────────────────────────────────────
  The check_absence_conflicts method intentionally checks status IN ('pending', 
  'approved') — not just approved. This is deliberate: a pending request should
  block new conflicting submissions from the same employee, otherwise two
  overlapping requests could both be pending and a supervisor might approve both
   without noticing. Conflict on submit prevents that race.
