● Root cause found. The CSV has double-encoded Polish characters — UTF-8 bytes
  were misread as CP1250, then those characters were saved as UTF-8 again. "ż"
  (bytes C5 BC) appears in the file as two chars Ĺ (C4B9) + Ľ (C4BD). The fix is
   to decode via encode('cp1250').decode('utf-8').

  ★ Insight ─────────────────────────────────────
  - This is classic mojibake (文字化け): ż in UTF-8 = bytes C5 BC. When those
  bytes were treated as CP1250 characters, 0xC5 = Ĺ and 0xBC = Ľ. Those two
  chars were then saved as UTF-8, giving C4B9 C4BD in the file. Reverse: encode
  the wrong chars back to CP1250 → get C5 BC → decode as UTF-8 → correct ż.
  - The diacritic-stripping approach in assign_category is still the right idea
  for category matching — once the names are fixed, strip_diacritics("masaż")
  correctly gives "masaz" because ż (U+017C) NFD-decomposes to z + combining dot
   above.
