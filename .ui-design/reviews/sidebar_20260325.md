# Design Review: Sidebar Navigation

## Summary

Sidebar jest wizualnie dobrze zaprojektowany z ciemnym motywem i przejrzystym grupowaniem sekcji. Jednak brakuje mu responsywnosci mobilnej (nie ma hamburger menu ani kolapsowania), a wewnetrzny system kolorow nie jest zsynchronizowany z design tokenami projektu. Interakcja hover-to-expand sekcji jest nieintuicyjna i moze kolidowac z click-to-toggle.

## Critical Issues

### C1: Brak responsywnosci mobilnej - sidebar jest niewidoczny na malych ekranach

**Severity:** Critical
**Location:** `sidebar.html` (caly plik) + `base.html:29-31`
**Category:** Usability

**Problem:**
Sidebar ma twardy `w-64` (256px) i brak jakiegokolwiek mechanizmu ukrywania/pokazywania na mobile. Na ekranach < 768px sidebar albo przepelnia viewport, albo zostaje ucieta przez `overflow-hidden` na rodzicu.

**Impact:**
Uzytkownicy mobilni nie maja dostepu do nawigacji. Przy uzyciu tabletu sidebar moze zajmowac zbyt duzo miejsca ekranowego.

**Recommendation:**
Dodac hamburger toggle w headerze, ukryc sidebar na mobile (`hidden lg:flex`), i dodac overlay sidebar na malych ekranach.

```html
<!-- base.html - dodac toggle button -->
<button id="sidebar-toggle" class="lg:hidden p-2 text-slate-600">
    <svg class="w-6 h-6" fill="none" viewBox="0 0 24 24" stroke="currentColor">
        <path stroke-linecap="round" stroke-linejoin="round" stroke-width="2" d="M4 6h16M4 12h16M4 18h16"/>
    </svg>
</button>

<!-- sidebar.html - dodac responsywne klasy -->
<aside class="hidden lg:flex w-64 bg-slate-900 text-white flex-col shadow-xl
              fixed inset-y-0 left-0 z-40 lg:static lg:z-auto
              transition-transform duration-300"
       id="sidebar">
```

### C2: Podwojna interakcja hover + click na sekcjach powoduje niespojne zachowanie

**Severity:** Critical
**Location:** `sidebar.html:317-342` (JavaScript)
**Category:** Usability

**Problem:**
Sekcje sidebara maja jednoczesnie `mouseenter` (rozwin sekcje, zwin inne) i `click` na headerach (toggle). Te dwa zachowania koliduja:

1. Uzytkownik najedza na "Salon" - rozwija sie
2. Klika header "Salon" - zwija sie
3. Rusza mysza w gore - `mouseenter` na "Finanse" rozwija inne sekcje
4. `mouseleave` z nav resetuje do stanu domyslnego

Uzytkownik nie wie, czy to klik czy hover kontroluje stan. Dodatkowo `mouseleave` na `.sidebar-nav` przywraca stan domyslny, co anuluje reczne klikniecia.

**Impact:**
Frustrujace i nieprzewidywalne zachowanie nawigacji. Uzytkownik nie moze polegac ani na hover, ani na click.

**Recommendation:**
Wybrac JEDEN model interakcji. Rekomendacja: click-to-toggle (bardziej przewidywalny, lepszy a11y). Usunac `mouseenter`/`mouseleave` eventy.

```javascript
// Usunac eventy mouseenter i mouseleave
// Zostawic tylko click-to-toggle
sections.forEach(function (section) {
    var header = section.querySelector('.sidebar-section-header');
    if (!header) return;
    header.style.cursor = 'pointer';
    header.addEventListener('click', function () {
        var items = getItems(section);
        var isExpanded = items && items.style.maxHeight && items.style.maxHeight !== '0px';
        if (isExpanded) {
            collapse(section);
        } else {
            expand(section);
        }
    });
});
```

## Major Issues

### M1: Kolory sidebar nie uzywaja design tokenow z input.css

**Severity:** Major
**Location:** `sidebar.html:1-8`, `sidebar.html:253`
**Category:** Visual

**Problem:**
Sidebar uzywa hardcodowanych klas Tailwind (`bg-slate-900`, `text-slate-400`, `border-slate-700/50`, `bg-slate-850`) zamiast CSS custom properties zdefiniowanych w `input.css` (`--color-ink`, `--color-surface`, `--color-border`).

Design tokens w `input.css` definiuja ciepla palete (`--color-surface-warm: #f7f6f3`, `--color-border: #e8e6e1`), ale sidebar istnieje w calkiem innej przestrzeni kolorow (cold slate).

**Impact:**
Jesli kiedykolwiek zmieni sie paleta kolorow (np. dark mode, rebranding), sidebar trzeba bedzie aktualizowac recznie - oddzielnie od reszty systemu.

**Recommendation:**
Dodac dedykowane tokeny sidebar do `:root` w `input.css`:

```css
:root {
    /* Sidebar Colors */
    --sidebar-bg: #0f172a;
    --sidebar-text: #94a3b8;
    --sidebar-text-active: #e2e8f0;
    --sidebar-border: rgba(51, 65, 85, 0.5);
    --sidebar-hover-bg: #1e293b;
    --sidebar-active-bg: rgba(37, 99, 235, 0.2);
}
```

### M2: Brak atrybutow ARIA na nawigacji akordeonowej

**Severity:** Major
**Location:** `sidebar.html:20-246`
**Category:** Usability / Accessibility

**Problem:**
Sekcje rozwijane (Finanse, Salon, Zarzadzanie, itd.) nie maja atrybutow ARIA:
- Brak `role="navigation"` na `<nav>`
- Brak `aria-expanded` na headerach sekcji
- Brak `aria-controls` laczacego header z items
- Brak `role="button"` na klikalnych headerach (sa `<div>` a nie `<button>`)
- Brak `aria-label` na ikonach SVG

**Impact:**
Czytniki ekranowe nie moga prawidlowo interpretowac nawigacji akordeonowej. Uzytkownicy klawiaturowi nie moga rozwijac/zwijac sekcji (brak focusable elements).

**Recommendation:**
```html
<nav class="sidebar-nav ..." aria-label="Menu glowne">
    <div class="sidebar-section" ...>
        <button class="sidebar-section-header ..."
                aria-expanded="true"
                aria-controls="finanse-items">
            Finanse
            <svg class="sidebar-chevron ..." aria-hidden="true">...</svg>
        </button>
        <div class="sidebar-section-items ..." id="finanse-items" role="region">
            ...
        </div>
    </div>
</nav>
```

### M3: Active state linku jest zbyt subtelny - niski kontrast

**Severity:** Major
**Location:** `sidebar.html:35` (powtarza sie w kazdym linku)
**Category:** Visual

**Problem:**
Aktywny link ma klasy: `bg-gradient-to-r from-primary-600/20 to-primary-600/10 text-primary-400 border border-primary-500/10`

To daje:
- Tlo: ~5% opacity niebieskiego na ciemnym tle (prawie niewidoczne)
- Tekst: `primary-400` (#60a5fa) na `slate-900` (#0f172a) - kontrast OK (~6.5:1)
- Border: 10% opacity - niewidoczny

Problem polega na tym, ze roznica wizualna miedzy stanem aktywnym a hover jest minimalna.

**Impact:**
Uzytkownik moze nie widziec, w ktorej sekcji sie znajduje (szczegolnie na monitorach o niskiej jakosci lub przy jasnym oswietleniu).

**Recommendation:**
Zwiekszyc kontrast active state:

```html
<!-- Mocniejszy active state -->
{% if request.endpoint == '...' %}
    bg-primary-600/20 text-white border-l-2 border-primary-400
{% else %}
    text-slate-400 hover:bg-slate-800 hover:text-white
{% endif %}
```

### M4: Sekcja "User Info" na dole nie jest wizualnie oddzielona od nawigacji

**Severity:** Major
**Location:** `sidebar.html:250-270`
**Category:** Visual

**Problem:**
Miedzy koncem nawigacji a sekcja "User Info + Logout" jest border-t (`border-t border-slate-700/50`), ale przy dlugiej liscie nawigacji uzytkownik moze nie widziec tej sekcji (scrollowanie wewnatrz `overflow-y-auto` na nav). Przycisk "Wyloguj" jest w oddzielnym divie ponizej, ale nie jest stickyowany do dolu.

**Impact:**
Na mniejszych ekranach przycisk wylogowania moze byc ukryty za scrollem nawigacji. Uzytkownik musi scrollowac w dol, zeby sie wylogowac.

**Recommendation:**
Struktura sidebar juz uzywa `flex flex-col` z `flex-1` na nav. To jest poprawne - user info i logout powinny byc sticky na dole. Sprawdzic, czy `overflow-y-auto` na nav nie powoduje obciecia. Dodac `shrink-0` na user info:

```html
<div class="px-4 py-3 border-t border-slate-700/50 bg-slate-850 shrink-0">
```

## Minor Issues

### m1: Powtarzajacy sie kod klas w kazdym linku nawigacji

**Severity:** Minor
**Location:** `sidebar.html:33-72` (i kazdy kolejny link)
**Category:** Code Quality (wplyn na utrzymanie wizualnosci)

**Problem:**
Kazdy link nawigacyjny ma identyczny blok klas (ok. 150 znakow) z jedynie rozniacym sie warunkiem `request.endpoint`. To ok. 15 kopii tego samego kodu CSS.

**Recommendation:**
Stworzyc Jinja2 macro:

```html
{% macro sidebar_link(url, label, icon_path, is_active) %}
<a href="{{ url }}"
   class="flex items-center gap-1 px-4 py-2 rounded-xl text-sm font-medium transition-all duration-200 group
   {{ 'bg-gradient-to-r from-primary-600/20 to-primary-600/10 text-primary-400 border border-primary-500/10' if is_active else 'text-slate-400 hover:bg-slate-800 hover:text-white' }}">
    <svg class="w-5 h-5" fill="none" viewBox="0 0 24 24" stroke="currentColor">
        <path stroke-linecap="round" stroke-linejoin="round" stroke-width="2" d="{{ icon_path }}" />
    </svg>
    {{ label }}
</a>
{% endmacro %}
```

### m2: Inline `style="filter: invert(1)"` na logo

**Severity:** Minor
**Location:** `sidebar.html:7`
**Category:** Visual

**Problem:**
Logo uzywa `filter: invert(1)` inline, co sugeruje ze oryginalne logo jest ciemne i musi byc invertowane dla ciemnego tla sidebar. To hack - jesli logo ma kolory inne niz czarny/bialy, invert znieksztalci je.

### m3: Gap `gap-1` jest zbyt maly miedzy ikona a tekstem linku

**Severity:** Minor
**Location:** `sidebar.html:34` (powtarza sie)
**Category:** Visual

**Problem:**
`gap-1` = 4px miedzy ikona SVG (20x20) a tekstem. Wg standardow Material Design i Apple HIG, minimalna odleglosc ikona-tekst to 8px (`gap-2`).

**Impact:**
Linki wygladaja na "scisnięte", ikona i tekst zlewaja sie wizualnie.

**Recommendation:**
Zmienic `gap-1` na `gap-2` (8px) lub `gap-2.5` (10px) we wszystkich linkach.

## Suggestions

### S1: Dodac animacje wejscia sidebar przy ladowaniu strony

Sidebar pojawia sie natychmiast bez zadnej animacji. Subtlene `animate-fade-in` (juz zdefiniowane w `input.css`) poprawilby postrzegana jakosc.

---

### S2: Dodac tooltip na ikonach gdy sidebar jest zwiniety (przyszlosc)

Jesli kiedykolwiek sidebar bedzie mogl byc zwiniety do icon-only mode, tooltips na ikonach beda kluczowe. Warto projektowac SVG ikony z `aria-label` juz teraz.

---

### S3: Rozwazyc uzycie `<details>/<summary>` zamiast custom JS dla sekcji akordeonowych

Natywny HTML `<details>` element daje:
- Wbudowana a11y (aria-expanded, keyboard)
- Zero JavaScript
- Animowalny przez CSS (`transition` na `max-height`)

## Positive Observations

- **Dobra struktura hierarchii**: Sidebar jest logicznie pogrupowany (Finanse, Salon, Zarzadzanie, Korekta, System) co odpowiada domenom biznesowym
- **Permission-based rendering**: Sekcje sa warunkowo wyswietlane na podstawie `user_permissions` - to bezpieczny wzorzec (server-side)
- **Spojne ikony**: Wszystkie ikony sa inline SVG Heroicons z identycznym sizing `w-5 h-5`
- **User avatar z inicjalami**: `current_user.full_name[:2].upper()` z gradientowym tlem to elegancki wzorzec bez koniecznosci zarzadzania obrazami
- **Lokalizacja rol**: Mapowanie rol na polskie nazwy (`superuser` -> `Superadmin`, `stylist` -> `Stylistka`) poprawia UX
- **Collapse/expand z chevron**: Wizualne wskazanie stanu rozwiniecia sekcji (obrot ikony) jest dobrym wzorcem
