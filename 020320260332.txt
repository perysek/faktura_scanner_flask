● ★ Insight ─────────────────────────────────────

  time and only includes classes it finds. If a class like invert or
  mix-blend-screen wasn't in any template when npm run build:css last ran, it

  modified), just a user_name and a new value like the IP address. Modelling

● ★ Insight ─────────────────────────────────────
  - The tab filtering is done entirely client-side — loadHistory() fetches all
  entries once, stores them in allEntries, and switchTab() just re-renders from
  that in-memory array. This avoids a round-trip per tab click and keeps the UI
  instant.
  - The _audit() helper in both route files uses try/except: pass deliberately —
   audit logging is a side effect and must never crash a business operation. The
   pattern "fire and forget, silent on error" is the standard approach for
  non-critical observability calls.
  - The DO $$ BEGIN ... EXCEPTION WHEN others THEN NULL; END $$ blocks in the
  migration are PostgreSQL's equivalent of "run this only if it hasn't been done
   already" — since ALTER COLUMN DROP NOT NULL fails if the column is already
  nullable, wrapping it in an exception block makes the migration idempotent and
   safe to run on every server restart.
